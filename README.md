# AI-помощник товарных описаний B2B

Локальное приложение на Python для подготовки черновиков карточек контрольно-измерительных приборов. Данные вводятся через веб-форму или JSON. Результат можно скопировать и скачать в JSON или Markdown. Дополнительно предусмотрен CLI.

Черновик требует проверки перед публикацией: приложение проверяет формат и объём, но не гарантирует достоверность свободного текста.

## Запуск

Требуются Python 3.10+ и [uv](https://docs.astral.sh/uv/getting-started/installation/). Из корня проекта:

```powershell
uv sync
Copy-Item .env.example .env
```

Заполните `.env`, затем выполните:

```powershell
uv run streamlit run app.py
```

Откройте адрес из вывода Streamlit, обычно `http://localhost:8501`. Заполните форму или выберите «Ввод через JSON». При предупреждениях подтвердите продолжение и запустите генерацию.

Без uv можно создать виртуальное окружение, установить зависимости из `requirements.txt` и запустить `python -m streamlit run app.py`.

## Настройка LLM

Провайдер, модель и подключение настраиваются через `.env` или переменные окружения. Аргументы CLI их не переопределяют. `.env` исключён из Git.

Gemini:

```dotenv
LLM_PROVIDER=gemini
LLM_MODEL=имя-доступной-вам-модели
LLM_API_KEY=ваш-api-ключ
LLM_BASE_URL=
LLM_OUTPUT_MODE=json_schema
LLM_TIMEOUT_SECONDS=120
LLM_MAX_RETRIES=2
LLM_FALLBACK_ENABLED=false
```

Локальный или облачный OpenAI-совместимый сервер:

```dotenv
LLM_PROVIDER=openai_compatible
LLM_MODEL=имя-модели-на-сервере
LLM_API_KEY=
LLM_BASE_URL=http://localhost:1234/v1
LLM_OUTPUT_MODE=json_prompt
LLM_TIMEOUT_SECONDS=180
LLM_MAX_RETRIES=2
LLM_FALLBACK_ENABLED=false
```

Укажите фактический адрес сервера и ключ, если требуется авторизация. Установка локальной модели находится за пределами проекта.

- `json_schema` передаёт схему через механизм структурированного ответа API; сервер должен его поддерживать.
- `json_prompt` передаёт схему в промпте и не требует `response_format` от OpenAI-совместимого сервера.

Оба режима включают локальную проверку ответа. Если сервер отклоняет режим схемы, выберите `json_prompt`.

Резервная модель необязательна. Для включения заполните `LLM_FALLBACK_*` в `.env.example` и установите `LLM_FALLBACK_ENABLED=true`. При отключённом fallback данные отправляются только основному провайдеру.

## Входные данные

```json
{
  "name": "Название прибора",
  "manufacturer": "Производитель",
  "specs": {
    "класс точности": "0,4",
    "присоединение": "резьба M20x1.5",
    "степень защиты": null
  },
  "description": "Описание или фрагмент технического паспорта"
}
```

- Название и производитель обязательны и не могут быть пустыми.
- Требуется описание либо хотя бы одна характеристика с известным значением.
- Значения в `specs` — строки либо `null`. Числа, массивы и вложенные объекты в значениях не поддерживаются.
- Пустое значение заменяется на «данных нет», показывается предупреждение и запрашивается согласие на продолжение.
- Отсутствующая характеристика не добавляется: универсальный перечень обязательных параметров не предполагается.
- Дубли ключей, в том числе после удаления внешних пробелов, и неизвестные поля верхнего уровня отклоняются.

Подтверждение неполных данных не разрешает додумывать сведения и не гарантирует генерацию: модель может сообщить о недостаточности информации.

## Результат и решения

| Поле | Содержание |
|---|---|
| `seo_title` | Заголовок до 70 символов |
| `seo_description` | Описание 800–1200 символов с пробелами |
| `specs_list` | Структурированный список характеристик |
| `search_queries` | 3–5 уникальных B2B-запросов |
| `commercial_block` | Аудитория и задачи прибора |

Характеристики собираются программно из входа с сохранением названий и значений, кроме удаления внешних пробелов и обработки пустых значений. Остальные блоки генерирует модель. Экспорт включает предупреждения, статус и метаданные: провайдера, модель, время, число обращений и факт fallback. `ready` означает прохождение реализованных проверок, а не готовность к публикации.

Промпты в `prompts.py` запрещают добавлять технические и коммерческие сведения, усиливать утверждения и терять ограничения применимости. Входной текст рассматривается как данные, а не инструкции.

При нарушении формата или длины допускается одна корректирующая генерация на маршрут. Она получает исходные данные, схему и предыдущий ответ как недоверенный черновик. Временные ошибки API повторяются в пределах `LLM_MAX_RETRIES`.

Fallback используется после исчерпания временных повторов или неудачного исправления ответа. Ошибки авторизации, конфигурации и явная недостаточность данных не обходятся резервной моделью.

## Примеры и CLI

В папке `examples/`:

- `product_1.input.json`, `product_2.input.json` — основные товары; рядом сохранены результаты `*.output.json`.
- `demo_pressure_gauge.input.json` — корректный пример для ручной формы.
- `warning_incomplete_data.input.json` — пустые данные для демонстрации предупреждений.
- `error_*.input.json` — намеренно некорректные данные для проверки ошибок.

Файлы `error_*` проверяйте через JSON-режим или CLI. Текущий загрузчик кнопок примеров преобразует значения при заполнении ручной формы в строки, поэтому не подходит для проверки исходных типов JSON.

```powershell
# Проверка без обращения к модели
uv run python cli.py -i examples/product_1.input.json --check-only

# Генерация JSON
uv run python cli.py -i examples/product_1.input.json -o output.json

# Экспорт Markdown
uv run python cli.py -i examples/product_1.input.json -f markdown -o output.md

# Продолжение при предупреждениях
uv run python cli.py -i examples/warning_incomplete_data.input.json -y -o output.json

# Справка
uv run python cli.py --help
```

Коды ошибок CLI: `2` — ввод, `3` — валидация, `4` — требуется подтверждение, `5` — конфигурация, `6` — генерация, `7` — пустой результат, `8` — сохранение файла.

## Проверки и ограничения

```powershell
uv run pytest -q
```

Автоматические тесты проверяют валидацию, CLI, настройки провайдеров, корректирующий запрос, повторы и fallback с подменой API, без реальных сетевых вызовов. Они не доказывают совместимость со всеми серверами или отсутствие галлюцинаций.

Автоматическая проверка каждого утверждения свободного текста не реализована; противоречия исходника могут остаться незамеченными. Перед публикацией необходима ручная вычитка. Поиск недостающих данных, чтение PDF, CMS и пакетная обработка не реализованы.

Возможные улучшения: проверка утверждений по источнику и сохранение исходных типов при загрузке ошибочных примеров через веб-интерфейс.
